1. INTRODUCCIÓN
---------------
El proyecto "Rally Fotográfico" consiste en el desarrollo de una aplicación móvil multiplataforma que permite organizar, gestionar y participar en rallies fotográficos. Los usuarios pueden inscribirse en eventos, recibir pistas, subir fotografías y recibir puntuaciones por parte de un jurado. El objetivo es fomentar la creatividad y el trabajo en equipo a través de la fotografía y la tecnología móvil.

La aplicación está dirigida tanto a organizadores de eventos como a participantes y jueces, facilitando la gestión integral del rally desde la inscripción hasta la evaluación de las fotografías.

2. ESTUDIO DE VIABILIDAD
------------------------

2.1 DESCRIPCIÓN DEL SISTEMA ACTUAL
Actualmente, la organización de rallies fotográficos se realiza de forma manual, utilizando herramientas como hojas de cálculo, correo electrónico y redes sociales para la comunicación y gestión de inscripciones, envío de pistas y recepción de fotografías. Este proceso es ineficiente, propenso a errores y no escalable.

2.2 DESCRIPCIÓN DEL SISTEMA NUEVO
El nuevo sistema automatiza y digitaliza todo el proceso mediante una aplicación móvil y un panel web de administración. Los organizadores pueden crear eventos, gestionar inscripciones y evaluar fotografías. Los participantes reciben pistas, suben sus fotos y consultan resultados en tiempo real. El sistema almacena toda la información en una base de datos centralizada y segura.

APÉNDICE I: ANÁLISIS DETALLADO DE LA CARPETA LIB (CÓDIGO FUENTE DART)
---------------------------------------------------------------------

Este apéndice describe en detalle la estructura, lógica y funcionamiento de todos los archivos Dart presentes en la carpeta `lib` del proyecto "Rally Fotográfico". Se analizan los servicios, pantallas, modelos y la arquitectura general de la aplicación.

I.1. ESTRUCTURA GENERAL DE LA CARPETA LIB
-----------------------------------------
La carpeta `lib` contiene todo el código fuente de la aplicación Flutter. Su estructura principal es:

- main.dart: Punto de entrada de la aplicación.
- firebase_options.dart: Configuración de Firebase.
- /screens: Pantallas principales de la app (UI).
- /services: Lógica de negocio y acceso a datos (Firestore, Storage, Auth).
- /assets: Recursos estáticos (imágenes, documentación, etc).

I.2. main.dart
--------------
Contiene el punto de entrada de la app y la lógica de enrutamiento principal. Inicializa Firebase y decide qué pantalla mostrar según el estado de autenticación y los datos del usuario (usuario normal, admin, bloqueado, o sin datos completos).

- Usa un widget `AuthGate` que escucha los cambios de autenticación y consulta Firestore para decidir la pantalla adecuada.
- Si el usuario está bloqueado, muestra `BlockedScreen`.
- Si faltan datos, lanza el flujo `ExtraInfoScreen`.
- Si es admin, muestra `HomeScreenAdmin`.
- Si es usuario normal, muestra `HomeScreen`.
- Si no está autenticado, muestra `LoginScreen`.

I.3. firebase_options.dart
-------------------------
Archivo autogenerado por FlutterFire CLI. Contiene las credenciales y configuración para conectar la app con Firebase en cada plataforma soportada.

I.4. /services
--------------
Contiene la lógica de negocio desacoplada de la interfaz. Cada servicio se encarga de una entidad o funcionalidad concreta:

- **auth_service.dart**: Lógica de autenticación (email/password y Google Sign-In). Permite login, registro y login con Google. Tras registro, crea el usuario en Firestore.
- **user_service.dart**: Gestión de usuarios en Firestore y Storage. Permite crear, consultar, editar y borrar usuarios, cambiar foto de perfil, editar username, bloquear/desbloquear usuarios y eliminar cuentas.
- **rally_service.dart**: Gestión de rallies. Permite crear, consultar, listar y borrar rallies, subir imágenes y comprobar si un rally ha finalizado.
- **fotos_service.dart**: Gestión de fotos subidas por los usuarios. Permite guardar, consultar, filtrar y borrar fotos, así como saber si un usuario ya ha subido foto a un rally. Al borrar una foto, elimina también los votos asociados.
- **voto_service.dart**: Gestión de votos sobre fotos. Permite votar, consultar el voto de un usuario, calcular la media de votos y borrar todos los votos de una foto.

Todos los servicios usan Firebase Firestore como base de datos y Firebase Storage para almacenar imágenes.

I.5. /screens
-------------
Contiene los widgets de interfaz de usuario (pantallas). Cada pantalla implementa una funcionalidad o flujo de la app:

- **login_screen.dart**: Pantalla de login y registro. Permite autenticación por email/contraseña y Google. Valida datos y lanza el flujo de información extra si es necesario.
- **extra_info_flow.dart**: Flujo para completar el perfil tras el registro/login. Solicita nombre, username, fecha de nacimiento y si es admin. Valida que el username sea único.
- **home_screen.dart**: Pantalla principal para usuarios normales. Muestra el listado de rallies, permite buscar, navegar a detalles, galería y perfil.
- **home_screen_admin.dart**: Pantalla principal para administradores. Permite buscar, crear y borrar rallies, gestionar fotos y usuarios, y acceder al perfil.
- **crear_rally_screen.dart**: Pantalla para crear un nuevo rally. Permite seleccionar foto, nombre y fecha de fin.
- **rally_detail_screen.dart**: Muestra el detalle de un rally activo. Lista todas las fotos aprobadas, permite votar con estrellas y subir una foto si el usuario no ha participado.
- **rally_finalizado_screen.dart**: Muestra los resultados de un rally finalizado, incluyendo la foto ganadora (mayor puntuación promedio), el usuario ganador y el nombre del rally.
- **galeria_screen.dart**: Muestra la galería personal del usuario, con el estado de sus fotos (revisando, aprobado, denegado) y permite votar en fotos aprobadas.
- **revision_fotos_screen.dart**: Pantalla para administradores donde revisan y gestionan las fotos pendientes (aceptar/denegar).
- **users_screen_admin.dart**: Pantalla de gestión de usuarios para administradores. Permite buscar, bloquear y desbloquear usuarios.
- **profile_tab.dart**: Pantalla de perfil de usuario. Permite ver y editar el perfil, cambiar contraseña, borrar cuenta y cerrar sesión.
- **blocked_screen.dart**: Pantalla mostrada a usuarios bloqueados. Permite cerrar sesión o eliminar la cuenta.

I.6. FLUJOS PRINCIPALES DE LA APP
---------------------------------
- **Autenticación**: El usuario inicia sesión o se registra. Si falta información, completa el flujo extra. Si está bloqueado, solo puede salir o eliminar la cuenta.
- **Gestión de rallies**: Los administradores pueden crear, listar y borrar rallies. Los usuarios pueden ver rallies activos y finalizados.
- **Participación**: Los usuarios pueden subir una foto a cada rally (si no ha finalizado y no han participado). Las fotos pasan por revisión de un admin.
- **Votación**: Los usuarios pueden votar fotos aprobadas (1-5 estrellas). La media de votos se muestra en tiempo real.
- **Gestión de usuarios**: Los administradores pueden buscar, bloquear y desbloquear usuarios. Los usuarios pueden editar su perfil, cambiar contraseña y borrar su cuenta.

I.8. EJEMPLOS DE USO DE LOS SERVICIOS
--------------------------------------
- Registrar usuario:
  ```dart
  await AuthService.register(email, password);
  ```
- Guardar datos de usuario:
  ```dart
  await UserService.saveUserData(
    uid: user.uid,
    email: user.email!,
    nombre: 'Juan',
    username: 'juanito',
    fechaNacimiento: DateTime(2000, 1, 1),
    esAdmin: false,
    areBaned: false,
  );
  ```
- Crear rally:
  ```dart
  await RallyService.saveRallyData(
    nombre: 'Rally Primavera',
    uid: adminUid,
    fechaFin: DateTime(2024, 6, 30),
    foto: urlFoto,
  );
  ```
- Subir foto:
  ```dart
  await FotosService.saveFotoData(
    rid: rallyId,
    uid: user.uid,
    estado: 'revisando',
    foto: urlFoto,
    username: user.username,
  );
  ```
- Votar foto:
  ```dart
  await VotosService.saveOrUpdateVoto(
    fid: fotoId,
    uid: user.uid,
    puntuacion: 5,
  );
  ```

I.11. DESCRIPCIÓN DETALLADA DE LOS PRINCIPALES ARCHIVOS DART
------------------------------------------------------------

A continuación se realiza un análisis exhaustivo de los archivos más relevantes de la carpeta `lib`, describiendo su estructura interna, funciones, lógica, dependencias y ejemplos de interacción entre ellos.

I.11.1. main.dart
-----------------
- **Propósito:** Es el punto de entrada de la aplicación. Inicializa Firebase y define la lógica de navegación principal.
- **Estructura:**
  - Inicialización asíncrona de Firebase.
  - Widget raíz `MyApp` que configura el tema y las rutas.
  - Widget `AuthGate` que determina la pantalla a mostrar según el estado de autenticación y los datos del usuario.
- **Lógica de navegación:**
  - Si el usuario está autenticado, consulta Firestore para obtener sus datos.
  - Si el usuario está bloqueado (`areBaned`), muestra `BlockedScreen`.
  - Si faltan datos obligatorios, muestra el flujo `ExtraInfoScreen`.
  - Si es admin, muestra `HomeScreenAdmin`; si no, muestra `HomeScreen`.
  - Si no está autenticado, muestra `LoginScreen`.
- **Dependencias:** Firebase Auth, Firestore, servicios propios, pantallas de UI.

I.11.2. firebase_options.dart
-----------------------------
- **Propósito:** Proporciona la configuración de Firebase para cada plataforma.
- **Generación:** Archivo autogenerado por FlutterFire CLI.
- **Uso:** Se importa en `main.dart` para inicializar Firebase con las credenciales correctas.

I.11.3. services/auth_service.dart
----------------------------------
- **Propósito:** Centraliza la lógica de autenticación.
- **Funciones principales:**
  - `login(email, password)`: Inicia sesión con email y contraseña.
  - `register(email, password)`: Registra un nuevo usuario y crea su documento en Firestore.
  - `signInWithGoogle()`: Autenticación con Google y registro en Firebase Auth.
- **Notas:** Tras el registro, se crea el usuario en la colección `usuarios` de Firestore.

I.11.4. services/user_service.dart
----------------------------------
- **Propósito:** Gestiona la información de los usuarios en Firestore y Storage.
- **Funciones principales:**
  - `userExists(email)`, `usernameExists(username)`: Validaciones de unicidad.
  - `saveUserData(...)`: Guarda o actualiza los datos del usuario.
  - `getUserData(email)`, `getUserDataByUid(uid)`: Obtiene datos del usuario.
  - `pickAndUploadPhoto(...)`: Permite seleccionar y subir una foto de perfil.
  - `editUsername(...)`, `saveUsername(...)`: Edición y validación del nombre de usuario.
  - `confirmAndDeleteAccount(...)`, `deleteAccount(...)`: Elimina la cuenta y todos los datos asociados.
  - `setBanStatus(email, ban)`: Bloquea o desbloquea un usuario.
  - `signOut(context)`: Cierra sesión.
- **Notas:** Gestiona la eliminación de fotos de perfil antiguas y la eliminación en cascada de fotos y votos al borrar un usuario.

I.11.5. services/rally_service.dart
-----------------------------------
- **Propósito:** Gestiona la entidad Rally (evento fotográfico).
- **Funciones principales:**
  - `saveRallyData(...)`: Crea un nuevo rally en Firestore.
  - `getRallyData(rallyId)`: Obtiene los datos de un rally.
  - `getAllRallies()`: Lista todos los rallies.
  - `deleteRally(rallyId)`: Borra un rally y todas las fotos/votos asociados.
  - `pickImage(context)`, `uploadImage(context, image)`: Selección y subida de imagen de rally.
  - `rallyFinished(rally)`: Comprueba si el rally ha finalizado.
- **Notas:** Al borrar un rally, elimina también las fotos y votos asociados.

I.11.6. services/fotos_service.dart
-----------------------------------
- **Propósito:** Gestiona las fotos subidas por los usuarios.
- **Funciones principales:**
  - `saveFotoData(...)`: Guarda una foto en Firestore.
  - `getFotoData(fotoId)`: Obtiene los datos de una foto.
  - `userHasFotoInRally(rid, uid)`: Comprueba si un usuario ya ha subido foto a un rally.
  - `getFotosByRally(rid)`, `getFotosByUser(uid)`, `getFotosByEstado(estado)`: Listados filtrados.
  - `deleteFoto(fotoId)`: Borra una foto y sus votos asociados.
- **Notas:** Elimina la imagen de Storage y los votos al borrar una foto.

I.11.7. services/voto_service.dart
----------------------------------
- **Propósito:** Gestiona los votos sobre las fotos.
- **Funciones principales:**
  - `saveOrUpdateVoto(fid, uid, puntuacion)`: Guarda o actualiza el voto de un usuario para una foto.
  - `votePhoto(context, fotoId, stars)`: Permite votar una foto desde la UI.
  - `getUserVoto(fid, uid)`: Obtiene el voto de un usuario para una foto.
  - `getAveragePuntuacion(fid)`: Calcula la media de votos de una foto.
  - `deleteVotosByFotoId(fid)`: Borra todos los votos de una foto.
- **Notas:** Permite que cada usuario vote una sola vez por foto.

I.12. EJEMPLOS DE FLUJOS DE USUARIO
-----------------------------------
- **Registro y primer acceso:**
  1. El usuario se registra con email/contraseña o Google.
  2. Si falta información, completa el flujo extra (nombre, username, fecha).
  3. Accede a la pantalla principal según su rol.
- **Participación en un rally:**
  1. El usuario selecciona un rally activo.
  2. Si no ha subido foto, puede subir una.
  3. La foto queda en estado "revisando" hasta que un admin la aprueba.
  4. Una vez aprobada, otros usuarios pueden votar la foto.
- **Gestión de rallies por admin:**
  1. El admin accede a la pantalla de gestión.
  2. Puede crear un nuevo rally, editar o borrar existentes.
  3. Puede revisar fotos pendientes y gestionar usuarios.

I.13. DISEÑO DE LA BASE DE DATOS FIRESTORE
------------------------------------------
- **Colección usuarios:**
  - Campos: uid, email, nombre, username, fechaNacimiento, esAdmin, areBaned, foto.
  - Índices: email (clave primaria), username (único).
- **Colección Rally:**
  - Campos: nombre, uid (creador), fechaFin, foto.
- **Colección Fotos:**
  - Campos: rid (id rally), uid (usuario), estado, foto (url), username.
- **Colección Votos:**
  - Campos: Fid (id foto), Uid (usuario), Puntuacion (int).
- **Relaciones:**
  - Un usuario puede tener muchas fotos.
  - Un rally puede tener muchas fotos.
  - Una foto puede tener muchos votos.
